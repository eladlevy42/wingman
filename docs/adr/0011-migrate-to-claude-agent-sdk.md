# Migrate BarneyAgent, NegotiationAgent, and softTurn to the Claude Agent SDK

## Context

`docs/adr/0003` chose the raw `@anthropic-ai/sdk` (Messages API) over the Claude Agent SDK specifically to avoid the Agent SDK's autonomous coding-agent machinery (filesystem/bash access, long-horizon task execution) for what is a simple structured chat-with-tools flow.

That tradeoff stopped winning once local/dev usage needed to authenticate via an existing Claude Code OAuth subscription login instead of provisioning `ANTHROPIC_API_KEY` per environment. `@anthropic-ai/sdk`'s client only accepts `apiKey`/`authToken`/`credentials`/`config`/`profile` — there's no supported OAuth-login path. The Claude Agent SDK does support it (`ApiKeySource` includes `'oauth'`).

The real package is `@anthropic-ai/claude-agent-sdk` (confirmed installable; CLAUDE.md's `@anthropic-ai/agent-sdk` does not exist).

### What the Agent SDK actually is

Investigating the installed package's type declarations (`sdk.d.ts`) before writing any migration code surfaced a material architecture mismatch with the raw Messages API this codebase was built against:

- The SDK's `query()` spawns the actual Claude Code CLI as a subprocess and drives it through a streamed, agentic session (`SDKMessage`s, permission/hook/tool-gating system) — it is not a thin client over `POST /v1/messages`.
- **There is no `tool_choice` forcing anywhere in the SDK.** `NegotiationAgent.score()` depended on `{ type: "tool", name: "saveScore" }` to force a single tool call. The Agent SDK has no equivalent — you can restrict _which_ tools are available (`tools`/`allowedTools`) but not compel the model to call one.
- **There are no `AuthenticationError`/`APIError`/`APIConnectionError` exception classes.** Errors surface as a string enum on `SDKAssistantMessage.error` (`'authentication_failed' | 'rate_limit' | 'overloaded' | 'invalid_request' | 'max_output_tokens' | ...`), not thrown types.
- The default tool surface is filesystem/bash-capable (`tools: { type: 'preset', preset: 'claude_code' }` or an explicit list) — exactly the extra attack surface ADR 0003 called out. Every call must pass `tools: []` to stay behavior-equivalent to a plain chat model.
- There is no per-call `max_tokens`/output-length cap in `Options` — only after-the-fact usage telemetry (`ModelUsage.maxOutputTokens`). The 400/1024/1500-token caps this codebase previously set per call site are not reproducible.
- `query()`'s `prompt` is a single string (or an async iterable of `SDKUserMessage`s for its own session/resume model) — there is no structured `messages: [...]` history array like the Messages API.
- The package declares a peer dependency on `zod@^4.0.0`; this repo is on `zod@3.25.76`. In practice `zod@3.25+` ships a `zod/v4` compatibility subpath that the SDK's types import from, so this works at runtime — `pnpm install` reports an unmet-peer warning, not a real break.

## Decision

Migrate all three call sites (`BarneyAgent`, `NegotiationAgent`, `softTurn`) onto `@anthropic-ai/claude-agent-sdk`, accepting the parity gaps above as unavoidable tradeoffs for OAuth-subscription auth in dev:

1. **Shared client (`apps/api/src/agents/agentSdkClient.ts`).** One `runAgentQuery()` wraps `query()` for a single bounded, _stateless_ call: full conversation transcript serialized into one prompt string, `tools: []` plus explicit `mcpServers`/`allowedTools` for anything custom, `permissionMode: "bypassPermissions"` (no interactive prompts in a server process), and `maxTurns` as the tool-loop bound. Retry/backoff (3 attempts, exponential) and error classification (auth → fail fast + distinct log; `rate_limit`/`overloaded`/`server_error` → retry; `max_output_tokens` → truncation error; anything else → fail fast) live here once, replacing the near-identical logic previously duplicated in `negotiation.agent.ts`, `barney.agent.ts`, and `softTurn.ts`.
2. **Stateless-per-call, not native session/resume.** Each turn spawns a fresh `query()` call with the full transcript replayed as text, mirroring the original design (each raw-API call also sent the full `messages` history). This was a deliberate choice over keeping one long-lived `Query` per session: it keeps the mental model and test shape close to the pre-migration code, avoids managing a subprocess's lifetime across Express request/response cycles, and sidesteps the SDK's own session persistence machinery, which solves a different problem (resuming a _Claude Code_ coding session) than replaying a two-party chat transcript.
3. **Forced tool_choice → prompt + re-ask.** `NegotiationAgent.score()` no longer forces `saveScore`; it restricts `allowedTools` to just that one MCP tool, instructs the model in the prompt to call it, and re-asks once (mirroring the previous one-retry-then-throw shape) if the model replies without calling it. This is best-effort, not a guarantee — nothing in the SDK prevents the model from replying with text instead.
4. **Tool schemas move to zod.** `saveProfileTool`/`saveScoreTool` (JSON Schema + a hand-rolled `handler(input, userId)` called manually after inspecting `tool_use` blocks) become `createSaveProfileTool`/`createSaveScoreTool` factories built on the SDK's `tool()` + `createSdkMcpServer()`, using the existing `UserProfileSchema`/`NegotiationScoreInputSchema` zod objects' `.shape` directly (both are plain `z.object()`s with no top-level `.refine()`, so shape-only validation is equivalent to a full `.parse()`). The SDK invokes the handler itself as part of its own agentic tool loop and validates input against the schema before calling it — the previous "catch `ZodError`, return an `is_error` tool_result so the model can self-correct" pattern is now handled by the SDK automatically; **BarneyAgent's `toolCall` event only fires on a successful, already-persisted save** (there is no more separate invalid-input event to listen for — see `barney.service.ts`'s `onToolCall`).
5. **`persistProfile` stays a plain exported function** (`apps/api/src/agents/tools/saveProfile.ts`) for the deterministic interview engine (docs/adr/0004), which assembles and validates a profile itself and never goes through the LLM tool-call path.

## Consequences

- `apps/api/package.json` drops `@anthropic-ai/sdk` entirely; `@anthropic-ai/claude-agent-sdk` is the only Anthropic dependency.
- CLAUDE.md §2's "AI Core" row now correctly names `@anthropic-ai/claude-agent-sdk`.
- Per-call `max_tokens` bounds are gone — cost/latency runaway is now only bounded by `maxTurns` (tool-loop iterations) and whatever internal defaults the CLI subprocess uses.
- The "does the model actually call the required tool" guarantee that `tool_choice` gave `NegotiationAgent.score()` is now probabilistic (prompt + one re-ask), not enforced by the API.
- Auth-failure/transient/truncation classification, and the retry/backoff policy, are now centralized in `agentSdkClient.ts` instead of being copy-pasted per call site — a real simplification independent of the auth-method motivation.
- Tests for all three agents now mock `runAgentQuery` (unit-testing each agent's own prompt/history logic) plus a dedicated `agentSdkClient.test.ts` that mocks the SDK's `query()` directly to cover retry/error-classification/text-and-tool-use extraction — the old `vi.mock("@anthropic-ai/sdk", ...)` per-file setup is gone.
- Fixed in passing: `negotiation.agent.ts`'s `writeRationale()` had a pre-existing duplicate `const response = await this.callModel();` declaration and orphaned code (a leftover merge artifact, unrelated to this migration) — resolved as part of rewriting the file.

## Update (issue #410) — `permissionMode` must be `"dontAsk"`, not `"bypassPermissions"`, on a root/sudo host

**Problem:** every soft-node interview turn, side-question, and negotiation turn returned an uncaught 500. Root cause: `runOnce` (`agentSdkClient.ts`) and `ensureStarted` (`agentSdkSession.ts`) set `permissionMode: "bypassPermissions"`. The underlying `claude` CLI subprocess unconditionally refuses `--dangerously-skip-permissions` when the host process runs as root/sudo — "`--dangerously-skip-permissions cannot be used with root/sudo privileges for security reasons`" — a hard, non-configurable safety guard in the CLI itself (confirmed: setting `allowDangerouslySkipPermissions: true` does not change this). The subprocess exits with code 1 before ever reaching the API, which the SDK surfaces as a bare `Error: Claude Code process exited with code 1` thrown directly from its process transport — bypassing `classifyAssistantMessage` entirely, since no session/message ever existed to classify. Many container/CI/cloud-sandbox setups (including the one this bug was diagnosed and fixed in) run their Node process as root, so this was not an isolated dev-machine quirk.

**Decision:**

1. **`permissionMode: "dontAsk"` replaces `"bypassPermissions"`** in both `agentSdkClient.ts` and `agentSdkSession.ts`. Verified live (real API calls through this repo's own `runSoftTurn`/`createWarmSoftTurn`/`answerSideQuestion`, plus a synthetic custom-MCP-tool call) that `"dontAsk"` avoids the root/sudo guard entirely, requires no `allowDangerouslySkipPermissions`, and still runs every custom tool successfully — because `tools: []` disables all built-in Claude Code tools and every custom tool is explicitly pre-approved via `allowedTools`, `"dontAsk"`'s "deny if not pre-approved" behavior never actually denies anything this codebase calls. Also verified live end-to-end through `negotiation.agent.ts`'s `runNegotiation()` (a throwaway script instantiating two fabricated participants): a full bounded 4-turn deliberation completed against the real API with no subprocess crash, producing a genuine `matched`/`scoreA`/`scoreB`/deliberation-log result — confirming the fix holds for `runAgentQuery`'s per-call (non-session) path, not just the warm-session path.
2. **A new `AgentSdkUnavailableError`** (`agentSdkClient.ts`) classifies subprocess-transport-level failures (process exit/termination/spawn failure — matched by message shape via `isProcessLevelFailure`, since the SDK exports no dedicated class for these) as a type distinct from `AgentAuthError` and from an ordinary `Error`. Raised in both `runOnce` and `agentSdkSession`'s `run()`, and deliberately **not retried** (a dead subprocess environment will not self-heal in 500ms–2s).
3. **Route handlers** (`barney.routes.ts`) now catch `AgentAuthError`/`AgentSdkUnavailableError` distinctly and respond `503` with an actionable "AI service temporarily unavailable" message, instead of falling through to the generic `500 Internal server error` — directly addressing this issue's "not indistinguishable from any other unexpected server error" acceptance criterion. `InterviewEngine.evaluate()` and the side-question call site in `handleMessage()` (`interview.engine.ts`) now log which node/field was in progress before rethrowing, for operator diagnosability, without changing the error's type or the failure's propagation.
4. **Orchestration** (`orchestration.service.ts`) already had adequate defense-in-depth from #339/#378 (`NegotiationTurnFailure` catches any turn failure, persists the partial transcript, and falls through to the best-available fallback; `runOrchestrationTick`'s per-user `try/catch` prevents one bad negotiation from aborting the sweep or crash-looping the interval) — left unchanged, since `AgentSdkUnavailableError`'s distinct `.name`/message now flows through `error.message` into the persisted `MatchAttemptFailure` and the console log either way.

**Consequences:** the actual root cause is fixed for every call site that goes through the shared `agentSdkClient`/`agentSdkSession` (BarneyAgent, NegotiationAgent, softTurn, sideQuestion, addendum, evalJudge, groundednessJudge, consistencyJudge) — not just a defensive wrapper — on any host that runs as root/sudo, which is common for containerized/CI/cloud dev environments. This does not change the _actual_ permission surface at runtime: since `tools: []` + explicit `allowedTools` already meant nothing outside those explicitly-opted-in tools could ever run, `"bypassPermissions"` was doing no more privilege-widening than `"dontAsk"` already does for this codebase's call shape — the change is a compatibility fix, not a security relaxation.
